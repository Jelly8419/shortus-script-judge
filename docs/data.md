# 데이터 구성과 선택 이유

## 무엇을 모았나

쇼더스에 가입해 직접 숏폼을 만들고, **대본 단계(렌더링 전)에서 멈춘 뒤** 원문과 대본을 수집했다. 원문은 URL을 다시 가져온 것이 아니라 쇼더스 입력 단계에 표시되는 **"제작에 사용한 원문"**, 즉 생성기가 실제로 받은 텍스트다. 수집은 스튜디오 화면에서 원문·섹션별 대본·예상 초를 내보내는 브라우저 스크립트(`tools/export_script.js`)로 했다.

원문 글자 수는 정제 전 기준. 모든 대본은 기본 설정(목소리 Aria, 1.1배속)으로 만들었다.

**고른 방식.** 과제 설명의 입력 유형(뉴스·블로그·커뮤니티 글·제품 소개)을 모두 넣으려 했고, 쇼더스 "소재 찾기"의 분야(정치·경제·연예·스포츠·생활·게임)도 섞었다. 수집하면서 분야보다 **입력 장르와 위험 신호**가 판정 기준을 가른다는 걸 알게 되어(결정 D9), 뒤쪽 샘플은 비어 있는 장르를 채우는 쪽으로 골랐다.

**사람 판정.** 11건 모두 판정기를 만들기 전에 직접 판정했다 (`data/labels.json`: 통과/보류, 결함 유형, 문제 섹션, 확신도, 판정을 바꾼 이력). 보류 7 / 통과 4.

## 왜 쇼더스로 직접 만들었나 (유튜브 쇼츠 스크립트 대신)

1. **판정 대상과 같은 분포.** 판정기가 실제로 볼 대본은 쇼더스 생성기의 출력이다. 사람이 쓴 쇼츠 스크립트는 오류 유형이 다르다. 실제로 수집한 대본에서 나온 결함(범위 확대, 기자 해석을 인물 반응으로 옮기는 귀속 오류, 유보 표현 삭제)은 "원문을 요약하는 생성기"에서 생기는 전형적인 실수다.
2. **원문이 있어야 기준을 판정할 수 있다.** 이 판정기의 핵심 기준은 "시청자가 원문과 다른 사실을 믿게 되는가"다. 쇼더스는 생성기가 쓴 원문을 그대로 보여주지만, 일반 유튜브 쇼츠는 무엇을 보고 썼는지 알 수 없어 사실 대조가 불가능하다.
3. **같은 구조.** 훅·포인트·통계·행동 유도 같은 섹션과 섹션별 예상 초가 그대로 있어, 결함 위치를 섹션 단위로 라벨링하고 "판정기가 그 섹션을 잡았는가"까지 검증할 수 있었다.
4. **써 보면서 발견한 것이 설계가 됐다.** 원문 추출이 실패해도 대본이 만들어지고 서비스 확정 검사(섹션 5~300자, 첫 섹션이 훅, 100초 이내)를 통과하는 사례(s04) → 입력 검사 단계. 포털 하단 안내문·관련 기사가 원문에 섞여 들어오는 것 → 원문 정제. 영상 입력 후보 단계의 자체 점수가 항목 점수와 맞지 않고 자극적인 후보를 1등으로 고르는 것 → "LLM 자기평가를 그대로 믿지 않는다"는 원칙.

## 넣지 않은 것과 이유

| 제외 | 이유 |
|---|---|
| 영상 입력 (유튜브 영상 → 쇼츠) | 대본을 새로 쓰지 않고 원본 구간을 고른 뒤 음성 인식 자막을 붙이는 흐름이라, 품질을 좌우하는 요소(인식 정확도, 구간 선택)와 검증 방법이 다르다 (D4) |
| 네이버 블로그 | 원문을 가져오지 못해 대본이 생성되지 않았다 |
| 유튜브 쇼츠 스크립트 | 원문이 없어 핵심 기준(원문 대비 사실 왜곡)을 판정할 수 없다 |

## 결함 주입 세트

실제 11건은 기준을 만들면서 본 데이터라 **개발셋**이다. 판정기가 처음 보는 결함으로 확인하려고, 사람이 통과로 판정한 s02·s05·s09에 원문 사실을 이용해 결함을 하나씩 심은 7건과, 원문 사실로 바꿔 쓴 대조군 3건을 따로 만들었다 (`data/injected.jsonl`, `data/labels_injected.json`). 결함 유형은 사실 오류 2, 귀속 오류 2, 범위 확대 1, 확실성 변화 1, 의미 왜곡 1.

## 한계

- **양이 적다.** 실제 대본 11건이라, 판정 1건이 흔들리면 지표가 9%p씩 움직인다. 그래서 버전 비교는 3회 반복 다수결로 했다.
- **주입 세트는 원문이 개발셋과 같다.** 완전히 새로운 기사에 대한 검증은 아니다.
- **설정이 하나뿐이다.** 목소리·배속·톤 옵션을 바꾼 대본은 없다.
- **사람 판정자가 한 명이다.** 판정자 간 일치도를 재지 못했다. 경계 사례(s03의 "월즈" 누락 등)는 확신도와 판단 근거를 라벨에 남겼다.

## 다른 데이터를 넣고 싶을 때

- 쇼더스에서 만든 대본: `tools/export_script.js`로 내보내 `npm run judge -- --data <파일>.jsonl`
- 대본 한 건을 붙여넣어 시험: `npm run judge:one -- --source source.txt --script script.txt` (원문이 있는 대본이면 유튜브 쇼츠 스크립트도 가능)
